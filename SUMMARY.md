# Ordered Work — Consolidated Design Summary

Status: `0.3.0-alpha.80`; profile-backed Split/Merge/Order and Work Control UI implemented. Legacy work lists removed; final deep runtime test pending.

## 1. Vision

One Work Control mod for RimWorld 1.7:

- Order a pawn’s work by a horizontal lane of WorkTypes, not by a numeric matrix.
- Preserve the vanilla job system: WorkTypes are containers; WorkGivers provide jobs; Jobs are runtime.
- Make configuration comfortable, fast and optionally autonomous.
- Work with a normal colony first; ordering is a mid-game improvement, not a requirement from minute one.

Part of a three-mod suite (standalone-first, optional integration): Work Control, Medical Hub, Security/Response. Each mod has its own internal core; no shared core in v1.

## 2. Primary decisions

- Primary input: **horizontal lane** of WorkType cards/chips; add/drag; left→right = priority; dense rank 1..N; numbers hidden.
- Below the lane: **read-only result table** for verification; not the main editor.
- Global WorkType/WorkGiver order is **secondary/default/fallback**; per-pawn lane overrides WorkTypes. WorkGivers keep their global `priorityInType`.
- WorkTypeDef is the primary unit; WorkGivers collapsed; Jobs are generated by the game.
- Vanilla Work tab is not replaced in the first slice; writes go to `Pawn_WorkSettings`.
- Managed pawns only; NPCs, animals and unmanaged mechs untouched.
- No work deletion; split/merge only, with safety.
- Each mod ships its own core; shared core only if duplication proves painful.

## 3. UI

- Full-screen **bottom tab** (`MainTabWindow`) “Work Control”.
- Primary lane: WorkType cards, add (`+`) or drag, left→right priority; absent = off; grey = incapable.
- Secondary: **Overview** comparison (choose a skill of interest, then one WorkType; rank pawns) and a read-only result table.
- Advanced per-pawn tab:
  - WorkTypes list;
  - outfit + tool rule;
  - special priority time windows;
  - general schedule (vanilla Work/Joy/Sleep + modded assignments);
  - key WorkType info (skills, speed, capacities, task count, derived recipe skills/requirements);
  - general restricted zone.
- Selection/hover states; responsive layout; horizontal slide/scroll for long names.
- Visual options: passion flame/quality estimate, compact icon + full name, skill level always or hover.
- No matrix as primary input; no dual editing.

## 4. Data model

- `BaseOrder`: global WorkType/WorkGiver defaults; optional editor.
- `ProfilePreset`: role/ordered jobs, loadout, area, schedule, rules.
- `PawnBinding`: pawn → preset(s); per-pawn lane.
- `PawnOverrides`: sparse per-pawn changes.
- `RoleSlot`: colony-level durable slot; survives pawn death; auto-assign.
- `CompiledPawnOrder`: runtime effective order; not saved.
- `WorkTypeRule` (new): per pawn/WorkType outfit/tool/stand/time rule.
- `ScheduleTemplate`/`WorkTypeTimeWindow`: per-WorkType priority windows.
- `BulkZonePolicy`: zone assignment to groups/emergency.
- Save presets/roles/bindings/overrides/settings; recompute effective order/ranks/giver lists.
- Death: park bindings/overrides; restore on resurrection; new pawns auto-assign.

## 5. Work hierarchy

- `WorkTypeDef` = office/column; `relevantSkills` is a list (Hunting = Shooting + Animals).
- `WorkGiverDef` = task inside a type; has no skill field; owns `workType`, `priorityInType`, tags/capacities.
- `Job` = concrete work; `JobDriver` executes.
- Skills: `WorkTypeDef.relevantSkills` (authored), `RecipeDef.workSkill`/`skillRequirements`, `Bill.allowedSkillRange`, `JobDef.joySkill`, code. Do not group/assign by a single skill.
- Vanilla stores priorities per WorkType in `Pawn_WorkSettings.priorities` (`DefMap<WorkTypeDef,int>`), saved with the pawn; no per-giver priority.
- `CacheWorkGiversInOrder` builds normal/emergency lists; `JobGiver_Work` walks them.

## 6. Equipment / Outfit Stands

- **Outfit Stand is Odyssey DLC**, not base vanilla. It stores one outfit (apparel + weapons) and swaps gear slots; jobs `UseOutfitStand`/`PutApparelOnOutfitStand`.
- No vanilla mannequin; `VFEM2_MannequinStand` is a tailoring linkable.
- Target design: one stand per workstation/room, linked to a pawn; outfit+stand owned by one pawn; temporary ownership while worn; emergency recovers the outfit from its recorded location.
- Trigger on WorkType change, not every job; target <0.5 in-game hours equipped and working; skip if path/equip exceeds limit; no swapping while drafted/emergency/downed.
- Multiple outfits are the hard case: one stand toggles two outfits; one stand per workstation distributes outfits. V1 can start with one work outfit per pawn/role; multi-stand/locker later.
- Future Simple Sidearms-like switching; Security/Response emergency path to nearby armor; per-WorkType outfit priority for specialists.
- Armor Racks is an optional provider if a 1.7-compatible version exists.
- Medicine/drugs are deferred to Medical Hub.

## 7. Zones and rooms

- One allowed area per pawn; zone is a constraint, not a priority.
- No WorkType zone recommendation.
- Easy pawn/profile zone assignment plus a bulk/emergency zone tab.
- Room assignment is discarded; assigned workbenches/rooms decide who works where.
- Warn if the current area can block the active WorkTypes.

## 8. Schedule

- Keep the global lane as the base order.
- In the advanced per-pawn tab, each WorkType can have start/end windows where it gains priority.
- Active windows jump ahead if jobs exist; overlapping windows are resolved by the global lane order.
- If no boosted jobs exist, fall back to normal order; never lock/limit work.
- No separate 24h matrix; a regular Schedule view edits the vanilla Work/Joy/Sleep timetable; per-WorkType windows live in the advanced tab.
- Unique benches per pawn can add noise; schedule stays optional.

## 9. Lane visuals

- Passion flame for the relevant skill; multi-passion mods show the passion representing the pawn for that task.
- Quality stars only for quality-producing WorkTypes; label as estimate.
- Compact icon + full name on hover/tooltip; horizontal slide/scroll.
- Skill level always or only on hover.
- View-only, cached.

## 10. Multi-pawn jobs

- Vanilla work is single-pawn: WorkGiver → Job → JobDriver. Group behavior uses Lord/LordJob/LordToil (rituals, parties, sieges).
- Researched mods:
  - **MultiHunter** (3560890077): multiple hunters on one animal; overwrites reservation; 1.6; taming/training side effects reported.
  - **MultiConstruction** (3562530209): multiple builders/repairers; diminishing returns; 1.6; author warns broken; accidental multi-mine without speed bonus.
  - **MultiTending** (3561607586): multiple doctors on different wounds; 1.6.
  - **Multi-Doctor Surgery** (3356249192): lead surgeon + assistants; 1.7/1.6/1.5.
  - **Team Builders** (3570660265): Call Builders/Min Builders; incompatible with MultiConstruction.
  - **Bulk Load For Transporters** (3559292908): multi-pawn loading; requires Pick Up And Haul.
  - **Colony Groups/WorkGroups**: grouping/role assignment, not native multi-actor jobs.
- No dedicated MultiMining found. MultiConstruction may accidentally multi-mine; not a supported feature.
- Mining/tool reference: **Forced Tools** (1.7/1.6) adds pickaxe/tool tiers, auto fetch/swap, hard mode; relevant to ores that need the right tool. **Axe and Pick Tools** and **More and Better Deep Drill** are adjacent.
- Integration: compatibility/detection first; do not reimplement reservations; mark team-capable WorkTypes/roles; coordinate schedules/outfit stations; use APIs or Lords; test minimal.

## 11. Technical findings

- `Pawn_WorkSettings.LowestPriority` is a **const**; reflection `SetValue` throws.
- `Pawn_WorkSettings.priorities` is a private `DefMap<WorkTypeDef,int>`; direct writes bypass the `SetPriority` clamp.
- The spike writes dense rank directly; `GetPriority` shows values >4; the vanilla Work tab displays large numbers.
- Manual vanilla editing still clamps to 0–4 (UI/`SetPriority`); our lane must use the direct writer.
- Vanilla `naturalPriority` may not control the visible Work tab order in a modded UI (Compact Work Tab/UIRethemed Work); needs a technical spike.
- `BeginScrollView/EndScrollView` must be protected from exceptions in test actions.

## 13. Exclusions

- No full compatibility with Work Tab/Better Work Tab/Enhanced Work Tab/WorkRoles/Compact Work Tab/PriorityMaster/More Work Priorities while replacing the Work tab.
- No own schedule tab, apparel system, area system, drug/food system, or work-permission system.
- No room assignment.
- No drugs in Work Control.
- No per-pawn per-giver numeric priorities in v1.
- No auto outfit per job without cooldown/time budget.
- No shared core across the three mods in v1.
- No work deletion.
